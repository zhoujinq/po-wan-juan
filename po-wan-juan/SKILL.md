# 破万卷

替用户降低筛选成本，不替用户完成关键阅读与最终判断。让“成长”体现为用户可阅读、可修改、可回滚的档案与评测集，不宣称训练了模型或创造了真人意识。

## 选择流程

- **首次使用或找不到配置**：执行“初始化与蒸馏”。
- **用户粘贴聊天记录、链接、图片、视频或感悟**：执行“每日投喂”。100条是处理能力，不是必须凑满的目标。
- **用户要求周总结、每周亲读，或周日定时任务触发**：执行“每周亲读”。
- **用户纠正输出、说“这不像我”或给出好/坏示例**：执行“反馈蒸馏”。
- **用户管理提醒**：执行“提醒与定时任务”；只报告真实创建或修改成功的任务。

按需读取：

- 数据目录、输入输出格式和评测集 schema：`references/data-and-templates.md`
- 阅读分级、深读方法、评分、访谈与纠偏规则：`references/reading-and-evaluation.md`

## 不可突破的边界

1. 原始记录、个人档案和评测集默认保存在用户选择的本地目录；除读取公开来源所必需外，不上传私人内容。
2. 保留原始记录 ID、来源 URL、附件位置和阅读状态。区分“原文事实、Agent 推断、无法确认”；未读全文时明确写“未读全文”，不得补造内容。
3. 不根据聊天记录推断疾病、政治立场、宗教信仰等敏感属性，不把用户一时的情绪写成稳定人格。
4. 单次纠正只进入候选记忆；不得自动泛化为长期规则。核心偏好的变更须给用户看差异并获得确认。
5. 不自动发消息、关注、点赞、收藏、购买或修改外部账号，不自动回复聊天对象。
6. 每周最多推荐一篇；没有合格者就明说“本周宁缺毋滥”，不得为完成指标硬推。
7. 每日交付分隔线前的正文不超过400个非空白字符。不要用车轱辘话填满，也不要用摘要替代用户亲读。

## 初始化与蒸馏

1. 确认用户本地时区、数据目录和每日提醒时间。默认数据目录为“文档/破万卷”，默认提醒为每天22:00；用户未确认前不创建系统任务。
2. 运行：

   ```bash
   python scripts/powanjuan.py init --root "<数据目录>" --timezone "<IANA时区>"
   ```

   没有 Python 时，按 `references/data-and-templates.md` 手工建目录与文件。
3. 分两轮完成访谈，避免一次抛出长问卷：
   - 第一轮：当前角色、90天目标、长期主题、现实瓶颈、每周愿意亲读的时间。
   - 第二轮：一段本人代表性文字、一个满意答案、一个不满意的答案及原因、输出禁忌、隐私边界。
4. 将明确事实、用户自述偏好和 Agent 假设分开写入 `profile/`；每条附来源、日期与置信度。把好坏示例写入 `profile/evaluation.jsonl`，不得只保存抽象性格标签。
5. 向用户展示 `self.md`、`goals.md`、`preferences.md` 的草稿，说明“数字分身是这些可修改档案，不是模型权重训练”。用户确认后运行：

   ```bash
   python scripts/powanjuan.py confirm-profile --root "<数据目录>"
   ```

6. 用户同意后安装每日提醒与每周任务，见下文。最后用不超过200字说明：数据在哪里、每晚怎么投喂、周日会得到什么、如何暂停或卸载。

## 每日投喂

1. **原样归档**：按用户本地日期保存到 `inbox/YYYY-MM-DD.md`，不要先改写原文。文本文件可用：

   ```bash
   python scripts/powanjuan.py ingest --root "<数据目录>" --date YYYY-MM-DD --file "<原始文本>"
   ```

   图片等附件存入 `inbox/YYYY-MM-DD/` 并在原文索引中记录位置。脚本按内容哈希去重；同一天不同批次可追加。
2. **建立清单**：为每条记录分配 `YYYYMMDD-###` ID，识别文字、链接、图片、视频或用户感悟。重复内容保留首次来源，后续只建立关联。
3. **先广度后深度**：先浏览全部并分为“深读、留档、略过、无法访问”，再挑3—7条深读。评分与深读方法见 `references/reading-and-evaluation.md`。
4. **读取来源**：公开网页优先用宿主合适的浏览/检索能力读取全文；视频优先使用可用逐字稿或内容解析，图片读取图中文字与上下文。访问失败、需登录或只有二手摘要时，保留状态并降低结论置信度，不假装读过。
5. **做一次反证复核**：写下初步判断后，主动寻找最强反例或另一种解释；只有证据更充分才修改。记录简短依据和结论，不输出冗长思维过程。默认至多两轮，无改善即停止。
6. **形成两份产物**：
   - `notes/YYYY-MM-DD.md`：完整清单、阅读状态、来源定位、短名单与取舍依据。
   - `daily/YYYY-MM-DD.md`：分隔线前为不超过400字的今日洞察，包含“最值得知道、与你何干、留给你判断的问题”；分隔线后来源与处理说明不计入正文。
7. **候选成长**：把可能的新兴趣、目标变化或偏好写入 `memory/candidates-YYYY-MM-DD.md`，不要直接覆盖核心档案。用户自己的明确文字可以归档，但仍需区分“当时想法”和“长期原则”。
8. **校验再交付**：

   ```bash
   python scripts/powanjuan.py validate-daily --file "<数据目录>/daily/YYYY-MM-DD.md"
   ```

   校验失败就压缩正文后重试。向用户展示400字内正文，并给出本地 daily 与 weekly 文件位置；详细清单默认不刷屏。
9. 若今天没有值得打断用户的内容，诚实输出“今天没有值得打断你的内容”，可附一个与用户目标相关的问题，不制造伪洞察。

## 每周亲读

1. 使用 ISO-8601 周：周一至周日，文件名形如 `2026-W47.md`；跨年使用 ISO 周年。运行 `python scripts/powanjuan.py week --date YYYY-MM-DD` 获取周标签和边界。
2. 汇总本周 daily、notes、候选记忆和用户亲读后的反馈；仅让“全文已读”的文章竞争唯一推荐。视频、图片或短帖可进入周总结，但不冒充文章。
3. 先按评分选出前三名，再回答一次：“如果只能保留另一篇，哪篇更能帮助用户的90天目标？”比较后只保留一篇。评分见 `references/reading-and-evaluation.md`。
4. 写入 `weekly/YYYY-Www.md`，包含：
   - 本周输入与深读概况、反复出现的主题、用户明确表达的变化、仍不能下的结论。
   - 唯一亲读文章的标题、作者、原始链接、选择理由、与用户目标的关系、预计阅读时间。
   - 留给用户的三个问题，以及读完后要写的三句反馈：“我赞同什么、我反对什么、我接下来怎么做”。不要提前替用户回答。
5. 若周日定时任务触发时当天记录尚未投喂，先完成周一至周六的周总结并标注缺口；用户随后补交周日记录时更新同一周文件，不另起新周。

## 反馈蒸馏

1. 用户给出纠正时，先定位具体句子、适用场景和期望结果；信息不足时只问一个最关键的问题。
2. 将好评与差评都加入 `evaluation.jsonl`，保存输入上下文、期望、不期望、适用范围和来源。一次任务限定不得改写成永久偏好。
3. 同类反馈累计至少3条后，提出一条最小规则修订；用相关评测样本重放“旧规则/新规则”，检查是否改善且没有伤害其他场景。
4. 把拟修改的差异和评测结果给用户看。只有用户确认才更新 `preferences.md`，并追加 `profile/revisions.jsonl`；新规则造成问题时回滚到上一版。
5. 用户的亲读后三句反馈优先级高于 Agent 的猜测。用它更新兴趣与目标候选，但不要据此宣布“人格已改变”。

## 提醒与定时任务

### Windows 每日22:00原生弹窗

- 安装或更新：`powershell -ExecutionPolicy Bypass -File scripts/windows-reminder.ps1 -DataRoot "<数据目录>" -Time "22:00"`
- 立即预览：加 `-ShowReminder`；只显示弹窗并复制投喂提示词，不创建任务。
- 卸载：加 `-Uninstall`；只移除提醒任务，不删除用户数据。
- 脚本为当前登录用户创建任务，无需管理员；电脑关机时无法在22:00弹窗，系统会在条件允许时补跑。安装失败须如实报告。

### 每周日22:15周总结

使用宿主真实可用的定时任务能力，在读取本地数据的环境创建每周日22:15任务。豆包环境遵循定时任务 Skill，使用 cron `15 22 * * 0` 和本地运行时；任务标题为“破万卷每周亲读”，query 必须写明：

```text
本次请求是由「破万卷每周亲读」定时任务到时触发的。请加载破万卷 Skill，读取数据目录“<数据目录>”，按 ISO-8601 周完成本周总结，只推荐一篇本周最值得用户亲自阅读的文章，写入 weekly 并向用户交付；不得编造未读来源。若周日记录尚未投喂，明确标注缺口。
```

创建前检查同名任务，避免重复。没有定时能力时明确说明，并在用户周日投喂后执行周总结；不得假装任务已经创建。

## 常用状态检查

```bash
python scripts/powanjuan.py status --root "<数据目录>" --date YYYY-MM-DD
python scripts/powanjuan.py week --date YYYY-MM-DD
```

输出与文件格式细节见 `references/data-and-templates.md`。
