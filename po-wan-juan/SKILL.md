# 破万卷

降低筛选与阅读成本，把关键阅读和最终判断留给用户。数字分身只是可阅读、可修改、可回滚的档案与评测集，不是训练完成的模型或真人意识。

## 知识地图与预访谈是可选步骤

- 知识地图及其预访谈**不是阅读或日报的前置条件**。有已确认或待确认的 `profile/knowledge-map.md` 就用它校准；没有地图，技能照样完整执行单篇阅读，以及用户指定「每日输入」时的一次出卡＋日摘。
- **只有用户明确要求初始化、重建或修订地图时，才读取 `references/knowledge-map-interview.md` 发起访谈。** 用户没提，就不发起、不追问、不等待、不暗示「先访谈效果更好」，也不为了后续测试向用户要地图。
- 没有地图时，卡片「与知识地图的关系」写「地图未就绪」，日摘「与你何干」同样写「地图未就绪」；两者都不得编造与用户目标、职业或处境的关系。

## 选择流程

- **单篇链接、图片、视频、书或一条随笔（默认路径，不需要地图）**：先按「阅读前的第一依据」看有没有地图可用，再读取 `references/carrier-workflows.md` 按实际载体执行，用 `references/reading-card-template.md` 输出一张卡片。没有地图直接读，不等访谈。
- **一条含多种内容的微信自聊 TXT**：先按时间戳、空行和 URL 拆条；链接与随笔分别阅读、分别出卡。一个容器文件可按任务要求保留一条容器级随笔卡，但不能拿总卡代替其中独立样本。
- **用户把「每日输入」交来并要求出卡＋日摘**：执行下文「一次批量处理的要点」。**只做这一次**：不装 22:00 提醒、不装转发插件、不连 Notion、不建计划任务；每日自动闭环需要用户另行确认，不因一次批量宣称已经交付。
- **用户明确要求初始化、重建或修订知识地图（可选路径）**：只有这时才读取 `references/knowledge-map-interview.md` 与 `references/knowledge-map-template.md`，分两轮访谈。格式示范见 `references/knowledge-map-example.md`，它只是虚构的「样例 / 待确认」，不是任何人的真实地图，不得当作已确认档案引用。
- **用户要求建立数据目录**：执行下文「初始化数据目录」。
- **用户要求周总结、每周亲读**：执行下文「每周亲读」。
- **用户纠正输出、说“这不像我”或给出好/坏示例**：执行下文「反馈蒸馏」。
- **用户管理提醒**：执行下文「提醒与定时任务」；只报告真实创建或修改成功的任务。

## 阅读前的第一依据

1. 先看有没有地图可用：用户已指定数据目录时，在其中查找 `profile/knowledge-map.md`；可并列保留 `self.md`、`goals.md`、`preferences.md`，但地图优先。**没有数据目录、没有地图，或用户没提地图，都不算缺前置条件**：不向用户要地图、不要求先初始化数据目录，直接进入阅读。
2. 有地图就用：地图可处于“已确认”或“待确认”状态。引用“待确认”条目时必须写明“待确认”，只能作为种子，不得写成已确认结论。
3. **没有已确认或待确认地图时，卡片的“与知识地图的关系”必须写“地图未就绪”，不得编造“与你何干”。**
4. 不为了建地图读取全量 Notion，不读取用户未授权的私人材料，不根据随笔推断人格或敏感属性。

## 初始化数据目录（用户要求时）

1. 确认用户本地时区、数据目录和每日提醒时间。默认数据目录为“文档/破万卷”，默认提醒为每天 22:00；用户未确认前不创建系统任务。
2. 运行：

   ```bash
   python scripts/powanjuan.py init --root "<数据目录>" --timezone "<IANA时区>"
   ```

   没有 Python 时，按 `references/data-and-templates.md` 手工建目录与文件。`init` 会建立一份“待确认”的空白知识地图，不覆盖已有文件。
3. 用户要求知识地图时再访谈（可选），写入 `profile/knowledge-map.md`；把好坏示例写入 `profile/evaluation.jsonl`，不得只保存抽象性格标签。
4. 向用户展示档案草稿，说明“数字分身是这些可修改档案，不是模型权重训练”。用户确认后运行：

   ```bash
   python scripts/powanjuan.py confirm-profile --root "<数据目录>"
   ```

5. 用户同意后安装每日提醒与每周任务，见「提醒与定时任务」。

## 一次批量处理的要点

1. **原样归档**：有数据目录时，按用户本地日期保存到 `inbox/YYYY-MM-DD.md`，不要先改写原文。文本文件可用：

   ```bash
   python scripts/powanjuan.py ingest --root "<数据目录>" --date YYYY-MM-DD --file "<原始文本>"
   ```

   脚本按内容哈希去重；同一天不同批次可追加。图片等附件存入 `inbox/YYYY-MM-DD/` 并在原文索引中记录位置。
2. **建立清单并去重**：为每条记录分配 `YYYYMMDD-###` 或任务指定的稳定 ID，识别文字、链接、图片、视频或用户感悟。把清单写成 JSONL（每行含 `id` 与 `url`、`text`、`path` 之一），用 `scripts/powanjuan.py dedupe-items` 在批次内去重，有数据目录时可加 `--root` 与历史批次比对。重复内容保留首次来源，后续只建立关联。
3. **先广度后深度**：先浏览全部并分为“深读、留档、略过、无法访问”，再挑 3—7 条深读。评分与深读方法见 `references/reading-and-evaluation.md`。100 条是处理能力，不是必须凑满的目标。
4. **读取来源并反证复核**：按「单篇阅读硬步骤」执行。访问失败、需登录或只有二手摘要时，保留状态并降低结论置信度，不假装读过。
5. **形成三份产物**：`notes/YYYY-MM-DD.md` 完整清单（字段见 `references/data-and-templates.md`）；`cards/YYYY-MM-DD/<条目ID>.md` 阅读卡片，读不到的条目也保留卡片并如实标状态；`daily/YYYY-MM-DD.md` 日摘，分隔线前为不超过 400 字的正文，包含“最值得知道、与你何干、留给你判断”，分隔线后的来源与处理说明不计入正文。
6. **候选成长**：把可能的新兴趣、目标变化或偏好写入 `memory/candidates-YYYY-MM-DD.md`，不直接覆盖核心档案。用户自己的明确文字可以归档，但仍需区分“当时想法”和“长期原则”。
7. **校验再交付**：

   ```bash
   python scripts/powanjuan.py validate-daily --file "<日摘路径>" --require-sections
   ```

   校验失败就压缩正文或补齐小节后重试。向用户展示 400 字内正文，并给出卡片、日摘的本地文件位置；详细清单默认不刷屏。
8. **不制造伪洞察**：若今天没有值得打断用户的内容，诚实输出“今天没有值得打断你的内容”，可附一个需要用户判断的问题。没有地图时，不写“与你目标相关”的问题。

用户没有指定输出目录时，卡片与日摘放在输入目录同级的新建输出目录，并在回复里写明路径。没有数据目录时，只在批次内去重，用 `validate-daily` 单独校验日摘。

## 单篇阅读硬步骤

1. 保留原始 URL、文件路径或消息时间，分配唯一条目 ID。
2. 实际打开来源后再判定载体，不根据文件名、标题、转发语或平台猜测内容。
3. 按 `references/carrier-workflows.md` 完成该载体的最低读法。图文必须读正文和文中图；视频必须读逐字稿并看关键帧；书按明确范围读到章节级。
4. 记录证据定位：段落/章节/页码、时间戳、字幕片段、图片序号或关键帧路径。只读摘要时，证据只能指向实际读到的摘要。
5. 做一次反证复核：写下初步判断后，主动寻找最强反例或另一种解释；只有证据更充分才修改。默认至多两轮，无改善即停止。
6. 用固定模板逐字段出卡；「与知识地图的关系」按「阅读前的第一依据」填写，没有地图就写“地图未就绪”。任何缺失能力都写成限制与本机补救，不补造正文、字幕、章节、图片或关键帧。

## 每周亲读

1. 使用 ISO-8601 周：周一至周日，文件名形如 `2026-W47.md`；跨年使用 ISO 周年。运行 `python scripts/powanjuan.py week --date YYYY-MM-DD` 获取周标签和边界。
2. 汇总本周日摘、阅读卡片、候选记忆和用户亲读后的反馈；仅让“全文已读”的文章竞争唯一推荐。视频、图片或短帖可进入周总结，但不冒充文章。
3. 先按评分选出前三名，再回答一次：“如果只能保留另一篇，哪篇更能帮助用户的目标？”比较后只保留一篇。评分见 `references/reading-and-evaluation.md`。
4. 写入 `weekly/YYYY-Www.md`，结构见 `references/data-and-templates.md`。包含本周输入与深读概况、反复出现的主题、用户明确表达的变化、仍不能下的结论；唯一亲读文章的标题、作者、原始链接、选择理由、预计阅读时间；留给用户的三个问题，以及读完后要写的三句反馈。不要提前替用户回答。
5. 没有合格文章时，把“本周唯一推荐”改为“本周宁缺毋滥”，说明原因。
6. 若周日定时任务触发时当天记录尚未投喂，先完成周一至周六的周总结并标注缺口；用户随后补交周日记录时更新同一周文件，不另起新周。

## 反馈蒸馏

1. 用户给出纠正时，先定位具体句子、适用场景和期望结果；信息不足时只问一个最关键的问题。
2. 将好评与差评都加入 `profile/evaluation.jsonl`，保存输入上下文、期望、不期望、适用范围和来源。一次任务限定不得改写成永久偏好。
3. 同类反馈累计至少 3 条后，提出一条最小规则修订；用相关评测样本重放“旧规则/新规则”，检查是否改善且没有伤害其他场景。
4. 把拟修改的差异和评测结果给用户看。只有用户确认才更新 `preferences.md` 或知识地图，并追加 `profile/revisions.jsonl`；新规则造成问题时回滚到上一版。
5. 用户亲读后的三句反馈优先级高于 Agent 的猜测。用它更新兴趣与目标候选，但不要据此宣布“人格已改变”。

## 状态与边界

- 阅读状态只能如实使用：全文已读 / 已看画面 / 仅摘要 / 未读全文 / 无法访问；可组合并附范围。
- 登录墙、失效链接、robots.txt 限制、只看到转发语：标“未读全文”或“无法访问”。不得把搜索摘要冒充原文。
- 无视频字幕：标“未读声音/未读全文”；无关键帧：标“未看画面”。两项缺一则不得声称视频完整验收。
- 全书未读完：标“未读全文（全书）”，逐章列出已读与未读范围。
- 原始记录、个人档案和评测集默认保存在用户确认的本地目录；除读取公开来源所必需外，不上传私人内容。不自动对外发消息、点赞、关注、评论、收藏或购买，不自动回复聊天对象。
- 不根据聊天记录推断疾病、政治立场、宗教信仰等敏感属性，不把用户一时的情绪写成稳定人格。
- 不擅自安装软件、创建计划任务、安装转发插件或连接 Notion。提醒脚本未获用户明确确认不得执行安装。一次批量处理同样遵守这条。

## 提醒与定时任务

### Windows 每日 22:00 原生弹窗

- 安装或更新：`powershell -ExecutionPolicy Bypass -File scripts/windows-reminder.ps1 -DataRoot "<数据目录>" -Time "22:00"`
- 立即预览：加 `-ShowReminder`；只显示弹窗并复制投喂提示词，不创建任务。
- 只看提示词：加 `-PrintPrompt`；只打印投喂提示词，不弹窗、不建任务。
- 卸载：加 `-Uninstall`；只移除提醒任务，不删除用户数据。
- 脚本为当前登录用户创建任务，无需管理员；电脑关机时无法在 22:00 弹窗，系统会在条件允许时补跑。安装失败须如实报告。

### 每周日 22:15 周总结

使用宿主真实可用的定时任务能力，在读取本地数据的环境创建每周日 22:15 任务（cron `15 22 * * 0`）。任务标题为“破万卷每周亲读”，任务内容必须写明：

```text
本次请求是由「破万卷每周亲读」定时任务到时触发的。请加载破万卷 Skill，读取数据目录“<数据目录>”，按 ISO-8601 周完成本周总结，只推荐一篇本周最值得用户亲自阅读的文章，写入 weekly 并向用户交付；不得编造未读来源。若周日记录尚未投喂，明确标注缺口。
```

创建前检查同名任务，避免重复。没有定时能力时明确说明，并在用户周日投喂后执行周总结；不得假装任务已经创建。

## 本地工具

`scripts/powanjuan.py` 只依赖 Python 标准库：

- `init`：初始化数据目录，并建立一份“待确认”的知识地图和卡片目录；不覆盖已有文件。
- `confirm-profile`：在用户明确确认后标记档案可用。
- `ingest`：原样追加一份记录，按内容哈希去重。
- `dedupe-items`：对条目清单做条目级去重，默认只检查不写入，`--commit` 才记录。
- `validate-daily`：校验日摘字数；加 `--require-sections` 时同时校验“最值得知道、与你何干、留给你判断”。
- `week`、`status`：ISO 周计算与状态检查。

个人数据目录必须在 skill 安装目录之外并由用户确认。运行脚本前读取相应参数，不覆盖已有个人文件。数据格式见 `references/data-and-templates.md`。
