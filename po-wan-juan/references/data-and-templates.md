# 数据与输出模板

## 目录

```text
<数据目录>/
├── config.json                 # 时区、周规则、提醒配置、档案确认状态
├── profile/
│   ├── self.md                # 用户确认的角色、经历、现实约束
│   ├── goals.md               # 90天目标与长期主题
│   ├── preferences.md         # 已确认的输出与阅读偏好
│   ├── evaluation.jsonl       # 好坏反馈评测集，一行一个 JSON
│   └── revisions.jsonl        # 核心档案的修改与回滚记录
├── inbox/                     # 原始投喂，不在这里写结论
│   ├── YYYY-MM-DD.md
│   └── YYYY-MM-DD/            # 图片、转写稿等附件
├── notes/                     # 每日完整清单与阅读轨迹
├── daily/                     # 每日400字内洞察与来源
├── weekly/                    # ISO周总结与唯一亲读推荐
├── memory/                    # 尚未确认的成长候选
├── state/                     # ingest-log.jsonl 等状态
└── runtime/                   # Windows提醒脚本副本
```

个人数据不得写回 Skill 安装目录。初始化脚本不得覆盖已有个人文件。

## 原始记录与索引

原文尽量原样保存。`notes/YYYY-MM-DD.md` 为每条记录建立索引：

| 字段 | 含义 |
|---|---|
| id | `YYYYMMDD-###`，同日稳定且唯一 |
| type | 文字、链接、图片、视频、用户感悟 |
| title | 原标题；无标题时写中性描述 |
| source | 原始 URL、附件相对路径或“用户输入” |
| read_status | 全文已读、仅摘要、无法访问、重复、略过、用户原文 |
| evidence | 支持结论的原文位置或简短引文 |
| relation | 与哪个90天目标、长期主题或历史记录相关 |
| decision | 深读、留档、略过及一句理由 |

原始记录 ID 与外部 URL 都要保留。只有二手转述时，结论必须指向实际读到的来源，不得把未读原文列为证据。

## config.json

```json
{
  "schema_version": 1,
  "display_name": "破万卷",
  "timezone": "Asia/Shanghai",
  "week_convention": "ISO-8601",
  "daily_reminder": "22:00",
  "weekly_review": "Sunday 22:15",
  "profile_confirmed": false,
  "profile_confirmed_at": null
}
```

时区应是用户真实 IANA 时区；不知道时使用 `local`，不要猜测。

## 个人档案写法

`self.md`、`goals.md`、`preferences.md` 使用短条目，每条保留：

```markdown
- 内容：90天内完成一个可公开展示的作品。
  类型：用户明确陈述
  来源：2026-11-19 初始化访谈
  最后确认：2026-11-19
  置信度：高
```

“Agent 假设”只能放入候选区，不与用户确认的事实混写。`preferences.md` 保存可观察规则，例如“先给结论，再给依据”，不要保存“理性、内向、认知高”等空泛标签。

## 评测集 evaluation.jsonl

每行一个 JSON 对象：

```json
{
  "id": "ev-20261119-001",
  "date": "2026-11-19",
  "context": "每日阅读输出",
  "input": "用户指出一条纠正前的原文或任务",
  "preferred": "先说与我90天目标的关系，再列证据",
  "rejected": "泛泛总结文章，没有说明为何值得我读",
  "scope": "每日洞察与每周推荐",
  "source": "用户明确纠正",
  "status": "active"
}
```

一次性要求必须写明具体任务范围。过期或撤回的样本将 `status` 改为 `retired`，不要删除历史。

## 每日洞察 daily/YYYY-MM-DD.md

分隔线前所有非空白字符（含标题）不得超过400个：

```markdown
# 2026-11-19 · 今日洞察

**最值得知道**：[一条最重要、证据充分的新信息。没有就直说没有。]

**与你何干**：[关联用户当前目标，指出具体影响，不奉承。]

**留给你判断**：[一个真正需要用户价值判断或经验的问题。]

---

## 来源
- [1] 记录 `20261119-003`；《标题》；原始 URL。
- [2] 记录 `20261119-017`；用户本人感悟。

## 处理说明
- 共收到X条；深读X条；全文已读X条；无法访问X条。
- [必要的“仅摘要/未读全文”限制。]
```

不要在正文罗列当天所有摘要。详细内容放 `notes/`。若当天信息不足，输出少量真话比凑满400字更好。

## 周总结 weekly/YYYY-Www.md

```markdown
# 2026-W47 · 本周亲读

## 本周回顾
- 输入与深读概况：[数量、缺口]
- 反复出现的主题：[只归纳有证据的主题]
- 你的明确变化：[来自用户本人文字或确认]
- 仍不能下的结论：[防止数字分身过度自信]

## 本周唯一推荐
- 标题与作者：
- 原始链接：
- 为什么是你：[对应哪个目标或困惑]
- 为什么是本周：[时机与不可替代性]
- 预计阅读时间：

## 带着这三个问题去读
1. 
2. 
3. 

## 读完只写三句
- 我赞同：
- 我反对：
- 我接下来：
```

推荐应留出原文中的关键论证让用户亲自读，不写“全文精讲”。没有合格文章时，把“本周唯一推荐”改为“本周宁缺毋滥”，说明原因。

## 成长候选与修订

候选记忆包含：候选内容、证据 ID、首次/最近出现日期、可能适用范围、相反证据、建议动作。不得直接并入核心档案。

`revisions.jsonl` 至少记录：日期、文件、旧内容、新内容、关联评测样本、用户确认、回滚指向。
